## 3. GitHubとAIを活用した「2人での進め方」ガイド

この基本設計をもとに開発を始める際、以下のように分担するとGitHubのワークフロー（Issue → Branch → Pull Request → Review → Merge）を綺麗に体験できます。

### ステップ1：初期構築（2人で一緒に作業）

1. 技術スタックやディレクトリ構成、コマンド、規約については `CLAUDE.md`（`AGENTS.md`）を参照して開発環境をセットアップする。
2. 上記の **「2.2 データベース設計」の表をもとに**、`apps/api/src/db/schema.ts` のテーブル定義とマイグレーションファイルを作成し、テスト用の初期データ（モックデータ10件分）を流し込む。

### ステップ2：タスク分割と並行開発（`gh stack` で stacked PR を作成）

初期データが入った状態から、2人で以下のように担当を分けます。`CLAUDE.md` の「PR の出し方」に従い、1つの機能につき **BE の PR を下、FE の PR を上にした stacked PR（`gh stack`）** で進めます。

- **担当者A：【一覧・検索パート】**
  - **1. BE の PR**（ブランチ例：`shop-list-api` / `gh stack init shop-list-api`）
    - `packages/schema` のスキーマ定義と `GET /api/shops` の実装
  - **2. FE の PR**（ブランチ例：`shop-list-web` / `gh stack add shop-list-web`）
    - BE ブランチの上に積み、**店舗一覧・検索画面**（カードUI、ステータスタブ切り替え、エリア・ジャンル絞り込み）を作成
- **担当者B：【登録・詳細・レビューパート】**
  - **1. BE の PR**（ブランチ例：`shop-crud-api` / `gh stack init shop-crud-api`）
    - `packages/schema` のスキーマ定義と `GET /api/shops/:id`・`POST`・`PATCH`・`DELETE` API の実装
  - **2. FE の PR**（ブランチ例：`shop-crud-web` / `gh stack add shop-crud-web`）
    - BE ブランチの上に積み、**店舗詳細画面・登録編集フォーム**（「行きたい→行った」の切り替えや★評価の入力UI）を作成
