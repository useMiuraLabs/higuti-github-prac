## 3. GitHubとAIを活用した「2人での進め方」ガイド

この基本設計をもとに開発を始める際、以下のように分担するとGitHubのワークフロー（Issue → Branch → Pull Request → Review → Merge）を綺麗に体験できます。

### ステップ1：初期構築（2人で一緒に作業）
1. リポジトリを作成し、使用する技術スタック（例：Next.js + Tailwind CSS + Prisma + SQLite / Supabase、または Python FastAPI + React など）を決める。
2. 上記の **「2.2 データベース設計」の表をそのままAIに貼り付け**、マイグレーションファイル（テーブル作成コード）と、テスト用の初期データ（モックデータ10件分）を生成させて流し込む。

### ステップ2：タスク分割と並行開発（別ブランチで作業）
初期データが入った状態から、2人で以下のように担当を分けます。

* **担当者A：【一覧・検索パート】**
  * ブランチ例：`feature/shop-list-and-search`
  * 担当範囲：`GET /api/shops` の実装と、**店舗一覧・検索画面**（カードUI、ステータスタブ切り替え、エリア・ジャンル絞り込み）の作成。
* **担当者B：【登録・詳細・レビューパート】**
  * ブランチ例：`feature/shop-crud-and-detail`
  * 担当範囲：`POST / PUT / DELETE` APIの実装と、**店舗詳細画面・登録編集フォーム**（「行きたい→行った」の切り替えや★評価の入力UI）の作成。
